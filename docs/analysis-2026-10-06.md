# Analysis 2026-10-06: what to make better, with pseudocode

A review of `feature/rich-text` after R1, R2 and B1, read against the code
(not the plan's snapshot line numbers). Findings come first, ranked by what
they cost the author: lost or wrong data, then wrong pixels, then speed,
then workflow. Each one has pseudocode for the fix. The queue in
[improvement-plan.md](improvement-plan.md#next-up-one-queue-update-when-a-task-lands)
stays the order of work; the new cards proposed here (S1, S2, L1) wait for
the author's word before they enter it.

## 1. Findings

### S1 (data): text and formatting are saved apart, so a crash can shift bold onto other letters

Today:

```text
TextInput::schedule_save      750 ms after the LAST edit  → storage.save_text(text)        transaction A
SylphApp::persist_model_*     750 ms after the FIRST format change (task not reset)
                                                           → storage.save_model(model)     transaction B
```

`char_formats` and `para_formats` are byte ranges over the text. If the app
is killed, crashes or loses power between A and B, the next open pairs the
new text with the old ranges (or the reverse): formatting lands on the
wrong letters, and nothing reports it. `save_snapshot` already writes both
in one transaction, but autosave never calls it. AGENTS.md's invariant "One
transaction per save" is broken in spirit.

Both writes also run inside `this.update(...)`, on the UI thread, with
`synchronous=FULL` (an fsync per commit). Typing does not stall because of
the 750 ms debounce, but each save is a frame-time fsync.

Fix in two steps. Step 1 is small and fixes the data; step 2 is plan
Phase 3's writer thread.

```text
// step 1: one save carries both (same thread as today)
on any text or format change:
    dirty_rev += 1
    save_task = after(750 ms) {                    // reset on every change: debounce from the last
        text  = editor.content.clone()
        model = app.document with formats from the editor
        json  = if model != persisted_model { Some(serde_json(model)) } else { None }
        result = storage.save_snapshot(doc_id, text, json)   // ONE transaction
        if ok and json: persisted_model = model
        save_state = from(result)                  // every error reaches SaveState
    }
remove: the separate formats_save_task; persist_model_now stays only for
        model-only changes that must save at once (page setup, cover)

// step 2 (Phase 3.x): the write leaves the UI thread
snapshot = (doc_id, text, json, dirty_rev)          // cloned on the UI thread
task = cx.spawn(async move |this, cx| {
    result = cx.background_spawn(writer.send(snapshot)).await   // a thread owning its own Connection (WAL)
    this.update(cx, |this| if this.dirty_rev == snapshot.rev { this.save_state = from(result) })
})
```

Regression test (step 1, fails today): pull the save into a function
`autosave(storage, doc_id, text, model, persisted) -> Result<..>` that the
timer calls. Test: make "word" bold, type before it (the ranges shift),
call `autosave` once, then reopen through `Storage::open_at` and assert
that the loaded ranges still cover "word". Today the text save alone
leaves the old ranges in `document_models`, so the assert fails.

### S2 (data): Restore brings back the text of a version but not its formatting

`save_revision` and `list_revisions` keep text only; `document_models` has
one row per document (the latest). `restore_revision` replaces the whole
text, and the edit maps the current ranges onto it. So bold, sizes, fonts
and alignment of the restored version are lost, and today's ranges are
dropped. R7's backup ("save the old text and model as a version") needs
the same thing, so S2 is a prerequisite of R7.

```text
schema step (Storage::open, before the window, never on the UI thread):
    if column crdt_updates.model_json is missing:
        ALTER TABLE crdt_updates ADD COLUMN model_json TEXT     // NULL for old rows

write_save(conn, doc, text, model_json: Option<&str>, new_row)
    INSERT/UPDATE crdt_updates(update_blob, model_json)          // the row carries its model

Revision { id, saved, text, model: Option<Document> }

restore_revision(rev):
    one undo step:
        content       = rev.text
        formats/paras = rev.model.map(|m| (m.char_formats, m.para_formats))
                                  .unwrap_or((empty, empty))      // old rows: plain, as today
        document.blocks/page setup stay (restoring text only, as today)
    save_revision(doc, content, model_json)                       // the restore is a version too
```

Tests: storage round trip (`save_revision` with a model → `list_revisions`
returns it; an old row returns `None`); desktop: restoring a version whose
model had bold on "word" makes "word" bold again.

### B2 (pixels): redraw requests made while drawing are dropped

`TextElement::prepaint` calls `window.refresh()` after a caret-follow
scroll and when the page count changes. GPUI 0.2.2's `refresh` returns
at once while drawing (`if self.invalidator.not_drawing()`), so the new
scroll offset, the new page sheet and the editor height show only after
the next input event. Being fixed now (plan queue #1):

```text
redraw::next_frame(window) = window.on_next_frame(|window, _| window.refresh())
    // next-frame callbacks run before the next draw, outside the draw phase
SYLPH_TRACE_FRAMES=1:
    toggle_emphasis → eprintln!("[frame] toggle Bold on=… rev=… range=…")
    TextElement::paint → eprintln!("[frame] paint rev=… pages=…")
```

### L1 (speed): every frame lays out the whole document

`prepaint` clones the text and every format, splits all lines into new
`String`s, builds display lines, wraps and shapes every row, and builds
hitboxes for every table, on every frame (caret blink, mouse move). GPUI's
line cache saves the glyph shaping but not the rest. A 50-page document
does all of that 60 times a second while the caret blinks. Plan 1.9 is
"partial" for this reason.

```text
struct LayoutKey { content_rev, format_rev, styles_rev, width, markdown_on, zoom }
struct RowCache  { key: LayoutKey, rows: Vec<RowMeta + RowText> }

prepaint:
    key = LayoutKey::from(input, bounds.width)
    if cache.key != key:
        cache = layout_all_rows(...)          // as today, once per edit or resize
    visible = rows whose box_top..box_bottom meets the scroll viewport (± one page)
    selection quads, line numbers, hitboxes: only for visible rows
    paint: only visible rows

format_rev: bumped wherever formats or para_formats change (toggle, size,
            font, alignment, undo/redo, load), next to content_rev
```

Acceptance: the plan's 1.9 counter (`SYLPH_TRACE_FRAMES=1` can print it)
shows one layout per edit and none while idle. Do it after R3, since R3
replaces the display-line builder this caches.

### Smaller findings

- **`persist_model_if_changed` runs after every notify** and compares the
  whole model (and, when it differs, clones it and compares again). It is
  O(model) per keystroke. S1's dirty counter replaces both compares.
- **The double-click drag** (B1) had no test and did not scroll: fixed on
  2026-10-06 (`word_drag_selection`).
- **main.rs is 8,200 lines, ui.rs 3,860.** Phase 1.12/1.13 are open.
  Rather than one big split, move the code a card is about to change into
  its module first, as a pure-move commit: S1 starts by moving
  `schedule_save`, `save_now*` and `persist_model_*` into `persist.rs`.

## 2. Pseudocode for the queued cards

### F1: font colour and highlight

```text
CharFormat += color: Option<Rgb>, highlight: Option<Rgb>      // "#rrggbb" in JSON; None = automatic
is_empty() also checks both

toolbar:  A▾  → palette(standard 10×6, custom hex, "Automatic")   → apply(selection | pending at caret)
          ▾highlighter → same palette + "None"
apply(range, f) = formats.apply(range, f); push_format_step; format_rev += 1

canvas  RowText::shape: TextRun.color = fmt.color.unwrap_or(style colour)
                        TextRun.background_color = fmt.highlight

        docx: run.font.color.rgb = RGBColor(rgb)
              highlight in WD_COLOR_INDEX if exact, else w:shd fill = rgb
one colour table: headings and inline code get explicit style colours, default black,
                  used by canvas, PDF and DOCX alike
```

### R3: the canvas draws rich documents

The point of the rich model: display text equals content, so the caret
mapping is the identity and the hidden-syntax code paths are skipped.

```text
rich_display_lines(text, paras, chars, objects, styles) -> Vec<DisplayLine>:
    numbers = ListNumbers::new()            // a counter per level; reset below a level on a shallower item
    for range in rich::paragraphs(text):
        para = paras.format_at(range.start)
        line = DisplayLine { source: range, text: text[range], prefix: None, indent: 0, font: styles.normal }
        match para.kind:
            Heading(n)            → line.font = styles.heading(n)
            ListItem{ordered, level, checked}
                                  → line.prefix = checked.map(box) or (ordered ? numbers.next(level)+"." : bullet(level))
                                    line.indent = (level + 1) * 18pt; wrapped rows hang at the text
            Quote(n)              → line.bars = n; line.indent = n * 12pt; italic per style
            Code{..}              → line.font = mono; line.shade = code background
            TableRow{table}       → line.cells = text[range].split(CELL_SEPARATOR)
                                    line.columns = objects[table].column_widths (else equal)
            Caption               → line.font = styles.caption
            None if text[range] == OBJECT_CHAR
                                  → line.object = objects[chars.format_at(range.start).object]
                                    Image: decoded off the UI thread, cached by path; PageBreak: flow.break_here
        if para.kind is not ListItem: numbers.reset()
        out.push(line)

caret ↔ x: prefix and indent shift x; the byte offsets are the content's own
old Markdown documents keep build_display_lines until R7
```

### R4: editing by paragraph kind

```text
Enter at caret in paragraph P (kind k):
    if k is ListItem and P is empty:   set P.kind = None              // Word: an empty item ends the list
    else: insert '\n' at caret          // the inserted '\n' ends the first half; the second half keeps P's own mark,
                                        // so it keeps k: lists continue, code continues
          if k is Heading or Caption: second half kind = None          // Enter after a heading gives Normal
Backspace at the start of P:
    if k in {ListItem, Quote, Heading}: P.kind = None                  // first Backspace removes the bullet
    else: delete the '\n' before P      // merge; the merged paragraph keeps the PREVIOUS paragraph's kind (Word)
Tab / Shift+Tab in a ListItem: level ± 1 (0..=8); Shift+Tab at level 0 → None
Markdown shortcuts, at a paragraph start, on the space that completes them:
    "# ".."###### " → Heading(n); "- " "* " → bullet; "1. " → numbered; "> " → Quote; "```" Enter → Code
    remove the marker; one undo step whose Ctrl+Z puts the literal marker back (Docs)
every one: one transaction for text + paras, format_rev += 1
```

### R7: open old documents as rich (needs S2 first)

```text
on open(doc) where !model.rich:
    (rich_model, text) = rich_doc::to_rich(model, content, markdown_on)
    one transaction:
        save_revision(doc, content, model_json(model))       // the backup, with its model (S2)
        save_snapshot(doc, text, model_json(rich_model))
    failure → open the old way, status bar says why (no silent fallback)
open questions for the author:
    - blank lines: keep them as empty Normal paragraphs (Word, Docs)? Then
      to_rich must see source lines, not export blocks:
          parse_content_blocks_with returns (Block, source_lines)
          for each blank source line outside a code block: emit Paragraph { runs: [] }
      and rich::to_blocks exports empty paragraphs (PDF/DOCX gain the same spacing)
    - restoring the backup gives a Markdown-model document, which the next
      open converts again. Mark the restored version "keep as Markdown"
      (a model flag) or accept the round trip.
```

## 3. Workflow

What went wrong this week, and what stops it next time:

| Problem | Seen as | Now |
| --- | --- | --- |
| Three cards (R1, R2, B1) sat uncommitted for days | one 1,200-line diff to review | one card = one commit; the report gives the commit message and the files |
| Machine changed (Arch → Debian), the `.venv` and libraries did not follow | 22 Python failures, a link error, a toolchain race | `scripts/doctor.sh`, run first by `verify.sh` |
| The plan grew four orderings and two model decisions | which card is next was unclear | one "Next up" queue at the top; replaced decisions marked |
| Behaviour change mixed with moves (B1 inside R1/R2) | harder review | pure moves first, in their own commit |

The loop for every card:

```text
doctor && verify python                 // start green; if not, fix the environment first
read the card; grep before trusting line numbers
if bug: write the failing test first
small steps, cargo check after each
verify python == ALL PASS
update status table + queue
report: files, tests, commands and results, VR checks, commit message
author: review diff → cargo run → commit
```

Optional, the author's call: a local pre-push hook that runs the ladder
(the repo has no CI). Not a symlink: `verify.sh` changes to its own
parent directory, which would be `.git`. Instead, by hand:

```sh
printf '#!/bin/sh\nexec scripts/verify.sh\n' > .git/hooks/pre-push && chmod +x .git/hooks/pre-push
```
